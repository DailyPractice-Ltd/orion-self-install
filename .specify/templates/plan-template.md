*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design. Any failure must be
either fixed or justified in Complexity Tracking below. See `.specify/memory/constitution.md`.*

- [ ] **Art. I — Library gate**: this feature belongs to a named library; not living only inside an app.
- [ ] **Art. II — Contract gate**: contracts exist in `contracts/`, reviewed, confirmed to compile/validate
  before implementation begins.
- [ ] **Art. III — Test-first gate**: tests written, confirmed failing, local CI green before implementation.
- [ ] **Art. IV — Reputation-safety gate**: if this feature touches outreach or buyer communication,
  a reputation-safety gate is specified with at least one boundary test case.
- [ ] **Art. V — Transparency gate**: all data flows are logged and auditable; no silent cross-client
  data movement; applicable legal disclosures identified.
- [ ] **Art. VI — Intelligence participation gate**: names the intelligence signal contributed,
  the route to the Intelligence Library, and the contribution cadence.
- [ ] **Art. VII — Simplicity gate**: does not add a 4th package/app without written, approved
  Complexity Justification.
- [ ] **Art. VIII — Abstraction gate**: any new abstraction cites three existing instances; no
  speculative abstractions.
- [ ] **Art. IX — Integration-test gate**: no mocks of databases, external APIs, or model calls
  in the integration/E2E suite.
